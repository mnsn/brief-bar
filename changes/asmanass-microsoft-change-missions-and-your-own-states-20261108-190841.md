- **The Board sets a pull request as next in another mission only where that frees it.** Where two missions' orders
  have a pull request you set as next to merge in one, the Board works out whether the first's order would hold it
  again were it next in the other, from the missions as they'd be then. So it sets it as next there once you moved what
  it waited for out of the first, or put that one after it with Merge After, rather than saying it would still wait;
  and where the first's order would hold it again, it says so, rather than only moving where it waits.
- **A stage names an order as you rename its mission.** Where two orders put pull requests the other way round, the
  stage that says to check the order names the other as its mission's header does as soon as you rename it, give it
  BriefBar's name back, or Apple Intelligence names it, rather than once BriefBar next reads your pull requests.
